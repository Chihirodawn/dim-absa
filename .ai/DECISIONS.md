# 技术决策记录

## DECISION-001：第一阶段只使用同一个 Instruct 模型

- 日期：2026-08-10
- 状态：已采用
- 背景：用户希望先验证无需训练的大模型判断能力。
- 最终选择：固定 Qwen3-4B-Instruct-2507，对比 direct、CoT 和 few-shot CoT，不创建 LoRA。
- 选择原因：控制模型变量，先验证 Prompt 与上下文示例的实际作用，避免过早引入训练成本。
- 影响范围：当前 Track A / Task 1 / 中文餐厅实验。

## DECISION-002：模型只生成数值，程序重建官方结构

- 日期：2026-08-10
- 状态：已采用
- 背景：官方要求 ID、方面原文、顺序及重复项准确，生成完整 JSON 容易改写文本。
- 最终选择：模型输出 `{"scores":[["V","A"],...]}`；代码使用原始 ID/方面词生成 `Aspect_VA`。
- 选择原因：将模型任务集中到 VA 判断，并降低格式错误。
- 后续注意事项：方面词显式编号，Prompt 写出精确数量；任何解析失败先做最多两次纯格式纠正并写入 diagnostics，仍失败才用训练均值补齐；有回退的结果不得报告。

## DECISION-006：用 dev 仿射校准解决 VA 刻度偏差

- 日期：2026-08-11
- 状态：已采用
- 背景：raw LLM 对变化方向有相关性，但过度使用 3/5/7/9，RMSE 甚至弱于训练均值基线，尤其高估 Arousal。
- 最终选择：在 dev 上为 V/A 分别拟合 `gold = slope * pred + intercept`，裁剪到 `[1,9]`；比较三种校准 dev RMSE 后锁定 few-shot，再仅应用冻结参数到 test。
- 选择原因：官方 Task 1 以 RMSE 为主指标；线性校准只修正模型尺度，不使用 test 标签，不训练 Qwen。
- 验证依据：few-shot dev RMSE 从 1.9836 降至 0.8940；test 从 2.0312 降至 1.1149，并优于 test 均值基线 1.4761。

## DECISION-011：动态检索作为差异化预测器，四路使用等权集成

- 日期：2026-08-12
- 状态：已采用
- 背景：动态 Few-shot 单路完整 Dev `1.1080`，略差于固定 Few-shot `1.0999`，但 A 相关性更高且错误模式不同。
- 最终选择：对 Direct、CoT、固定 Few-shot、动态 Few-shot 的原始 V/A 各取 25% 平均，再使用 Dev 拟合的 V/A 仿射参数；不使用 Test 选择或修改权重。
- 选择依据：按记录分组的 5 折交叉验证中，固定 Few-shot 为 `1.1133`，四路等权集成为 `1.0415`；自由线性权重和 Dev 网格权重没有更稳定，故选择最简单的等权方案。
- 最终验证：完整 Dev `1.0263`，Test `1.3662`；官方脚本一致，相比原 Test `1.4511` 改善约 5.85%。

## DECISION-020：Task 2/3 采用三视角结构投票与独立关系重评分

- 日期：2026-08-14
- 状态：已采用
- 背景：旧 Qwen 抽取器 Dev 结构能力尚可，但单一路径受 Few-shot 示例影响，且自由生成
  V/A 的数值误差会直接降低 cTP。
- 最终选择：保持旧 Qwen QLoRA 权重不变；用 word/bigram/trigram 三种 BM25 视角分别
  检索 3 条英文 Train 示例，精确 Aspect/Opinion/Category 至少两票才保留；再由部分解冻
  的英语情感 RoBERTa 单独回归每个关系的 V/A。
- Dev 选择：二票投票优于一票和三票；关系重评分的 seed42 优于三种子等权平均，差距
  小于 `0.01` 时按既定规则选更简单的 seed42。
- Test 边界：投票阈值、检索路数、示例数和种子在读取 Test 指标前冻结；Test 结果不再
  用于调参。最终 Task 2/3 cF1 为 `0.6165776036/0.5734562902`。

## DECISION-023：冻结旧二票结果，只做无训练保守补漏

- 边界：该改进远小于此前设定的 `0.01` 强提升门槛，先保留为低风险补丁，不自动运行

## DECISION-027：SemEval使用离散Aspect极性预训练，不伪造连续VA

## DECISION-028：Base模型同时比较部分解冻与全量微调，不使用LoRA

- 日期：2026-08-18
- 状态：已采用并执行完成。
- 背景：用户提出较小 Base 可能比 Large 更不易过拟合，并询问全解冻 LoRA 是否更好。
- 最终选择：RoBERTa-base 直接比较冻结编码器、解冻 4/8 层和全解冻 12 层；固定相同
  seed、损失、对比约束与采样方式，不把 LoRA 和全解冻混为同一变量。
- 原因：LoRA 冻结原始权重，不等于全量微调；当前模型与数据规模可直接承担全量对照，
  最终由 Dev 决定而不预设更多可训练参数一定更好。
- 边界：只看 Train/Dev，不运行 Test。
- 结果：0/4/8/12 层分别为 `1.1043478/1.0648936/1.0456768/1.0495504`；8 层最佳，
  全解冻略差。Base 未超过 Large，停止后续多种子和 Test。

## DECISION-029：公开数据使用共享编码器多任务头，不再只做顺序预训练

- 日期：2026-08-18
- 状态：已采用并执行完成，未超过当前最佳。
- 最终选择：固定 Large 后 8 层；DimABSA 使用序数＋Huber主损失、Ranking和二维 VA
  MoCo，EmoBank 使用整句 VA 辅助头，SemEval 使用 Aspect 极性辅助头。三个数据集不直接

  均未超过顺序预训练 `0.9169297`，因此停止额外种子和Test。
